# Review Loop / 复盘闭环：卡片到期之后发生什么

> 本项目参赛子主题是**信息提炼与信号生成**。复盘闭环不是另一个主题，它是让「信号生成」这个主张**可以被追责**的那一半：
> 一张写明了失效条件的卡片，在窗口关闭之前是一个承诺，**关闭之后就是一个可以判分的测试**。不判分的可证伪性只是修辞。

---

## 1. 为什么要有这一段

Prism 的每张卡都必须写「什么情况下我错了」，附**可观测的价格/数值水平**和**复检时间**。这在发行时看起来像是一种自律；但如果没有人回头去核对，它就只是一句好听的话。

所以管线在 PRESENT 之后还有一个阶段：

```text
PLAN -> INGEST -> EXTRACT -> VERIFY -> SCORE -> PRESENT -> REVIEW
                                                            └─ 窗口关闭后回头判分，只报告，不改规则
```

`REVIEW` 回答两个**经常被混为一谈**的问题：

1. **这个判断对吗？** 卡片自己写的失效条件有没有被触发？标的有没有朝主张的方向走出**相对于基准的实质幅度**？
2. **打分规则会排序吗？** 分数更高的卡，实现结果是不是更好？如果不是，五因子权重就是装饰，应该改。

---

## 2. 三条轴，永远分开算

| 轴 | 测什么 | 是否参与裁决 |
|---|---|---|
| **① 失效条件** | 收盘价有没有穿越卡片**自己写下的**那个数值水平，并且在其 `recheckAt` 复检日仍然成立。宏观 pair 是这条轴的一个特例：卡片写的是「2 个 session 内多头腿没有跑赢空头腿 50bp」，`walkPairSpread` 用发行窗口起的前 2 根日 K，价差 = 多头收益% − 空头收益%（不是半权重 payoff）。价差低于 0.50 个百分点，失效条件就触发 | ✅ **优先** |
| **② 风险路径** | `tradeSketch` 的止损 / 目标位在窗口内有没有被摸到 | ❌ **只报告，永不裁决** |
| **③ 实现超额** | 卡片自己窗口内、相对 SPY 的**带符号超额收益** | ✅ ① 未触发时用这个 |

**为什么 ② 不能裁决：**「这笔交易会不会疼」和「这个判断对不对」是两个问题。一张被止损扫掉但方向正确的卡，如果让 ② 来裁决，就会被记成一次失败——而这恰恰是**最该被学到的一课**（失效条件太紧），不该被记成判断错误。所以 ② 永远单独报告。

本轮实测：**12 条有数值止损/目标的主张里，② 与 ③ 的分歧是 0 条**。这个数字本身就是报告里的一条 INFO——它说明这批卡的风险区间设得不算激进，也说明分开报告目前还没付出代价。

## 3. 八个方法决定（每一个都会改变结论，所以都写明）

| # | 决定 | 为什么 |
|---|---|---|
| 1 | **窗口锚定 `createdAt`（发行时刻），不是 `informationAt`** | 卡片上每个价位都是**以发行时的价格为基准**敲定的。用 informationAt 去量，等于拿一个卡片自己窗口之外的参考价来判它 |
| 2 | **一律算超额，不算原始涨跌** | 同窗口对 SPY。否则一轮上涨的行情会被误记成本事。美元中性的 pair 按价差算——基准在构造上自动抵消 |
| 3 | **重述合并** | 看板每次运行都会重发同一主张。按 `claimKey` 折叠后统计，否则「命中率」会有三位有效数字而毫无意义。本轮 **345 张卡 → 162 个独立主张** |
| 4 | **实质性带 ±1%** | 窗口收在 ±1% 带内、且失效条件没有触发的，记为 `inconclusive`，**不硬塞进胜负栏**。本轮 6 条 |
| 5 | **同 bar 并列时判止损** | 日线 OHLC 无法排序盘中事件。同时触及止损与目标时**假定止损先到**——这个偏向**压低**命中率 |
| 6 | **不可测是一个裁决，不是一个缺口** | 卡片引用了价格库里没有的标的 → 记 `unmeasurable`，**绝不计入胜、负，也绝不悄悄丢掉**。本轮 31 条 |
| 7 | **非方向性单独列** | `neutral` / `hedge` 卡没有「方向对不对」可判，不进分母。本轮 29 条。macro-analyst 的桥接卡是中性的，所以它增加看板，不增加命中率分母 |
| 8 | **pair 按卡片自己的 50bp 门槛测，不按全窗口超额蒙混** | 以前这句没有可执行的序列，轴 ① 跳过。现在价差低于 50bp 就判失效，即使全窗口超额还落在 ±1% 带里。不可机器验证的主张从 24 降到 6；胜场仍是 10，决出胜负从 34 增到 39，命中率从 29.4% 降到 25.6%。**这不是策略变好了，是测试变严了。权重没有改** |

> `claimKey` 里包含**测量窗口**（from→to，以及是否被价格库末端截断）。这是刻意的：一个被截断的窗口和一个跑满到期日的窗口，即使结束日期相同，也是**两个不同的测试**。把它们合并会让一张仍然开着的卡继承一个用更短窗口量出来的裁决。

## 4. 它拒绝做的事

🔴 **复盘永远不会自动修改打分规则。**

它只报告。本轮 `rho(score, excess) = -0.137`（n=45），报告把它标成 **BLOCKER**——但即便标成 BLOCKER，系统也**不会**自己去动那五个权重。

原因很直接：45 条主张来自 **6 个不同的信息日期**，共享同一批文档、同一个基准、同一段宏观环境。它们**不是独立观测**。在这种样本上自动调参，等于把噪声拟合进规则，而且**再也没人能分辨**规则是被证据改的还是被运气改的。

**改规则必须是一次人类做的、写进 commit 的决定。** 这是设计约束，不是没做完。

同样地：

- 复盘**默认只读**。`--persist` 才写回，且只重分类**已终结**状态的卡片，**永不改动 active 卡**。
- 默认 `as-of` 锚定**价格库末日**（2025-09-30）而不是墙上时钟，所以同一条命令在任何一天跑都得到同一个答案。

## 5. 怎么跑

```bash
# 只读，打印摘要
node prism.mjs review

# 完整 markdown 报告
node prism.mjs review --report

# 从提交的看板 fixture 复现仓库里那份报告（推荐，见 §6）
npm run review:seed

# 指定裁决日 / 实质性带 / 写回
node prism.mjs review --as-of=2025-09-30 --materiality=1.5 --persist

# JSON（给别的程序用）
node prism.mjs review --board=data/fixtures/board-seed.json --json
```

HTTP（都是只读）：

```text
GET /api/review?asOf=2025-09-30
GET /api/export/review.md
```

Web 投研台：左栏 **Signal review** 面板。打开面板**不会**改动任何存储状态——要写回只能用 `--persist`。

## 6. 可复现性：为什么有一个提交的看板 fixture

这是本节存在的唯一理由，也是本项目最容易出问题的地方。

`data/state/board.json` 是**运行时状态，被 gitignore**。所以：

> 在一个全新 clone 上跑 `node prism.mjs review`，看板是空的，裁决 **0 条主张**——而 `docs/reports/review.md` 里写着一堆数字。一份没人能复现的报告，正是这个项目要反对的东西。

解法是把复盘所依据的看板做成**提交的 fixture**，并由一个固定回放计划重建：

```bash
npm run seed        # scripts/build-seed.mjs
npm run review:seed # 从该 fixture 重新生成 docs/reports/review.md
```

`scripts/build-seed.mjs` 用 **11 个固定的 as-of 日期 × 6 个 demo 场景 = 66 次运行**回放出一块看板，写到 `data/fixtures/board-seed.json`（**已提交**），并在文件里记录 `provenance`（回放日期、场景、数据模式、抽取器）。

**实测结果（本仓库构建环境）：**

| 产物 | 复现性 |
|---|---|
| `data/fixtures/board-seed.json` | 连续两次 `npm run seed`，**SHA-256 完全相同** |
| `docs/reports/review.md` | 连续两次 `npm run review:seed`，**除「Generated <时间戳>」那一行外逐字节相同**（差异 1 行 / 全文 190 行） |
| `data/state/board.json` | `npm test` 跑完**前后字节数不变**（测试已隔离到自己的 scratch 状态文件） |
| `docs/DEMO-TRANSCRIPT.md` | 从空看板重跑，除生成时间戳与每轮 `ms` 计时外**逐字节相同**（差异 7 行） |

一条时间戳的差异不是缺陷，是**如实记录**：报表写明了自己是什么时候生成的。除此之外，任何一个评委在任意一台机器上 clone 下来，都能得到同一批判分数字。

要做到这一点，先修掉了三个真实的可复现性漏洞：

| 漏洞 | 后果 | 修法 |
|---|---|---|
| 卡片 id 用 `Date.now()` 打戳 | `--as-of` 冻结了 `createdAt`，却**没冻结身份**：同一回放在不同日期产出不同 id，看板文件永远对不上 | `nextCardId(prefix, at)` + `rebaseCardId()`，在 `stampTime()` 里按 `createdAt` 重新打戳（序号后缀保留，唯一性不变） |
| 证据账本 `verifiedAt` 用 `new Date()` | 同一次 `--as-of` 回放每跑一遍就写出一个**不同的**看板文件 | 改用 `card.createdAt`（即运行时钟，见 `stampTime` 的注释） |
| `npm test` 会写真看板 | `POST /api/ask` 默认 persist，测试套件每次跑都往 `data/state/board.json` 里追加卡片——**这就是已发布数字对不上新 clone 的原因** | 测试套件用 `PRISM_STATE_FILE` 指到自己的临时文件并在 `after` 里删掉；`validate.mjs` 同样钉死到 scratch 文件 |

顺带产出两个部署需要的开关：`PRISM_STATE_FILE`（只读根文件系统 / 挂卷）与服务端识别 `HOST`/`PORT`（所有容器 PaaS 注入的就是这两个名字）。见 `DEPLOY.md`。

裁决日 **2025-09-30**，基准 **SPY**，实质性带 **±1%**，悲观并列规则 **开**。

| 统计量 | 值 |
|---|---:|
| 看板卡片 | 345 |
| 独立主张 | 162 |
| 窗口已关 | 105 |
| 窗口仍开（临时，不判） | 57 |
| 已裁决 | 45 |
| 决出胜负 | **39** |
| 胜 / 负 | 10 / 29 |
| 落在实质性带内（inconclusive） | 6 |
| **命中率** | **25.6%**（Wilson 95% CI 14.6–41.1%；精确 CP 13–42.1%） |
| 平均带符号超额 | -0.832% |

| 失效条件只有文字、无法机器验证 | **6**（可测的有 39） |

### 打分规则会排序吗？——不会，而且方向是反的

| grade | 区间 | 主张 | 决出 | 胜 | 命中率 | 平均超额 |
|---|---|---:|---:|---:|---:|---:|
| A | ≥75 | 10 | 9 | 2 | **22.2%** | -1.358% |
| B | 62–75 | 28 | 24 | 5 | 20.8% | -0.378% |
| C | 48–62 | 7 | 6 | 3 | **50%** | -1.896% |

**A 级卡的命中率低于 C 级卡。** 逐条审计里最刺眼的是那批 80 分的 `CAT` 空头：四个相邻窗口，三个 `LOST`，其中两个失效条件确实 `FIRED`、止损也确实被摸到。分数最高的卡是表现最差的一批。

按方向拆开更清楚：

| direction | 主张 | 决出 | 胜 | 命中率 | 平均超额 |
|---|---:|---:|---:|---:|---:|
| long | 11 | 9 | 5 | **55.6%** | +1.122% |
| pair | 18 | 16 | 2 | 12.5% | -1.189% |
| short | 17 | 12 | 1 | **8.3%** | -2.876% |
| avoid | 2 | 2 | 2 | 100% | +5.947% |

**这个窗口里，desk 的空头几乎是系统性错的（1/12）。** 按频道：`risk-flag` 2/2 全对，`narrative-shift` 2/4，`earnings-gap` 4/17，`macro-transmission` 2/16 最差。pair 从 2/11 变成 2/16，是因为 50bp 门槛把原先的平局改判成失败，不是因为多赢了。

### 报告给出的处置项

| 级别 | 发现 | 处置 |
|---|---|---|
| 🔴 **BLOCKER** | `score-predictiveness`：rho = -0.137（n=45），分数越高实现越差 | 在这个 rubric 上发布任何结论之前，先找出并修掉出问题的那个因子 |
| 🟠 WARNING | `coverage-gap`：31/105 张已关窗口的卡引用了价格库里没有的标的，**根本无法裁决** | 扩价格库，或者**不要**对 desk 事后无法判分的名义出方向性卡——实践中不可证伪的卡比没有卡更糟 |
| 🟠 WARNING | `untestable-falsification`：45 条里还剩 **6 条**的失效条件只是文字（例如「flags -> 0 for 2 quarters」）。宏观 pair 的「2 个 session 后价差 < 50bp」已经能被 `walkPairSpread` 执行 | 剩下的 narrative / risk 文字条件仍要收成数值水平 + 所指序列 |
| 🔵 INFO | `proxy-substitution`：44 张卡是透过声明的 demo 价格代理测量的 | 这些裁决描述的是**代理序列**，不是虚构发行主体。不要当成 issuer 级别的结果引用 |
| 🔵 INFO | `inconclusive-share`：6/45 落在 ±1% 带内 | 实质性带占比下降，主要是因为失效条件触发后优先于超额收益 |
| 🔵 INFO | `window-length`：中位 3 个交易日（区间 1–15） | 这么短的窗口分不开「好判断」和「运气好的两周」 |
| ✅ ok | `channel-spread`：最好 `narrative-shift` 50%（n=4），最差 `macro-transmission` 12.5%（n=16） | 频道之间确实有差异，但 n=4 不足以据此重新分配权重 |

## 8. 这份报告**不是**什么

- **不是回测。** 它审计的是「已发布的判断有没有活过它们自己写下的证伪测试」，**不是**「照着做能不能赚钱」。
- **不含任何成本。** 没有佣金、价差、借券费、滑点，也没有组合层面的聚合。一次「命中」是一个方向，不是一笔利润。
- **样本仍然太小。** 39 条决出胜负的主张来自 6 个信息日期，命中率的 Wilson 95% 区间是 14.6–41.1%（精确 CP 13–42.1%）——**比任何它能测出的效应都宽**。报告的第一句 caveat 就是「不应从本报告得出任何关于盈利能力的结论」。
- **主张之间不独立。** 同一个日期、同一批文档、同一个基准、同一段宏观环境。rho 和命中率是对**这块看板**的描述，不是对某个总体参数的估计。
- **虚构发行主体是透过代理测的。** `CRVS`/`HLXN`/`ASTR`/`BLWF`/`NWCL` 没有上市价格；在它们声明了 `priceProxy` 的地方，用那条真实序列测量，并在行上标注。

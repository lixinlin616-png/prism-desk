这个演示是什么

  • 演示页是 静态回放：所有接口响应都由 scripts/export-static.mjs 在导出时驱动真实离线引擎录制（含 SSE 逐帧节奏），浏览器端 web/static-adapter.js 原样回放。不是 mock，也不是手写数据。
  • 看板与复盘用仓库里已提交的 data/fixtures/board-seed.json（11 个固定 as-of × 6 个场景 = 66 次回放），所以页面上的复盘数字与 docs/reports/review.md 完全一致。
  • 静态页面确实做不到两件事：跑一个全新的自由提问、写入看板。遇到这两种情况页面会明说，不会假装成功。要实时后端：git clone 之后 node server.mjs（零依赖，不需要 npm install）。

建议的观看顺序

  • 演示台 — 先点 Full desk sweep / 全频道扫描，看 PLAN → INGEST → EXTRACT → VERIFY → SCORE → PRESENT 全流程；再点右侧看板任意一张卡，看它的证据账本与失效条件。
  • 左栏 Score the board — 窗口已关闭的卡用真实价格回头裁决，并报告"分数是否真的预测了结果"。
  • README · ARCHITECTURE · VALIDATION
  • 验证报告 · 复盘报告 · 提交材料逐条对照

这个工作台的三条主张

  • 每张信号卡必带失效条件：写不出"什么证据能证明它错"的主张不进看板。
  • 打分规则不自动调权：事后判分发现分数与结果负相关（rho −0.138）时如实公开为 BLOCKER，而不是悄悄拟合噪声。
  • 虚构与真实分开标注：演示发行人为虚构且显式披露借用的真实价格代理；价格数据本身是真实的。

# Roadmap / 后续路线

这份路线图的每一项都挂在一个**已实测的数字**上。没有"以后想做得更智能"这种条目——如果一个改动说不出它会改变哪个已发布的数字，它就不在这份路线图里。

排序原则：**先修 BLOCKER，再补观测，最后才是产品化。**

| 优先级 | 项 | 触发它的实测数字 | 做完能改变什么 |
|:--|---|---|---|
| 🔴 P0 | 修掉打分规则的符号反转 | rho = **-0.137**（n=45）；A 级命中 **22.2%** < C 级 **50%** | 让分数重新变成一个有意义的排序 |
| 🔴 P0 | 失效条件全部数值化 | **24 / 45** 条主张的失效条件无法机器验证 | 让轴 ① 真正裁决多数结论，而不是回退到超额收益 |
| 🟠 P1 | 禁止对无法判分的名义出方向卡 | **31 / 91** 不可测 | 消掉"实践中不可证伪"的卡 |
| 🟠 P1 | 扩大独立观测 | 45 条主张只来自 **6 个信息日期** | 让任何校准数字**够格被当成结论** |
| 🟡 P2 | 接入真实 rToken 盘口 | 流动性系数 **0.45 是估算** | tradability（权重 0.18）从猜测变成测量 |
| 🟡 P2 | 抽取质量系统对比 | 标注集只有 **10 例** | 规则路径 vs LLM 路径谁更好，第一次有答案 |
| 🟢 P3 | 成本与组合层 | 现有全部数字**不含任何成本** | 唯一能通往"盈利能力"结论的路径 |
| 🟢 P3 | live 端点端到端录制 | 构建环境**无外网**，全部走 fixture | 把 fixture 换成实时数据 |
| ⚪ P4 | 多用户与生产级持久化 | 单机 JSON 文件 | 真实使用，而非 demo |

---

## 1. 🔴 P0 · 修掉打分规则的符号反转

**证据。** `rho(score, realised excess) = -0.137`，n=45。分档更直白：

| grade | 主张 | 决出 | 命中率 |
|---|---:|---:|---:|
| A（≥75） | 10 | 9 | **22.2%** |
| B（62–75） | 28 | 19 | 26.3% |
| C（48–62） | 7 | 6 | **50%** |

按方向拆：**short 1/12（8.3%）**，long 5/9（55.6%）。逐条审计里最刺眼的是那批 80 分的 `CAT` 空头——四个相邻窗口三个 LOST，其中两个失效条件确实 FIRED、止损也确实被摸到。**分数最高的一批卡是表现最差的一批。**

**假设（尚未验证）。** `surprise` 权重 0.30，奖励"预期差大"。但一个已经跳空反映过的大 gap，是**拥挤**的交易，后续更可能均值回归——于是"gap 越大 → 分越高 → 实现越差"。空头尤其吃亏：这段窗口指数在涨，做空一个已经跌过的名字等于逆着 beta 走。

**怎么做（顺序不能颠倒）：**

1. 在 `src/review/adjudicate.mjs` 里输出**逐因子**的偏相关（每个因子得分 vs 实现超额），定位**是哪一个因子**携带了负号。现在只有总分对超额的相关，看不出是谁在 dragging。
2. 对那个因子做三选一：翻转符号 / 降权 / 加一个"已被定价"的前置守卫（例如 gap 当日已实现幅度超过 X% 就不再加分）。
3. 给 short 加一个**指数 regime 过滤**：基准处于上升趋势时，单边空头的 tradability 或 asymmetry 打折。
4. **在一段没参与调参的 as-of 区间上重跑复盘**，验收标准：held-out 区间上 rho ≥ 0。

🔴 **红线：这一步必须由人做完、写成 commit、在 commit message 里说明依据。绝不允许系统自动调权。** 理由见 `REVIEW-LOOP.md` §4——45 条主张来自 6 个信息日期、共享文档与基准，**不是独立观测**；在这种样本上自动调参等于把噪声拟合进规则，而且之后没人能分辨规则是被证据改的还是被运气改的。

## 2. 🔴 P0 · 失效条件全部数值化

**证据。** 45 条已裁决主张里，**24 条**的失效条件只是文字，没有可机器验证的水平：

- `narrative-shift`：「≥ 2 篇文档的语气符号翻转」——没有说清是哪个 tone 分数、阈值多少
- `macro-transmission`：「2 个 session 后 pair 价差对 SPY < 50bp」——有阈值，但**没有指明用哪条序列去算这个价差**
- `risk-flag`：「被公司明确解决 + 比率连续两个季度正常化」——纯文字

结果是轴 ① 对这 24 条**无法裁决**，只能回退到轴 ③（实现超额）。也就是说：**过半的结论并不是在检验 desk 自己写下的话。**

**这是本路线图里性价比最高的一项**——它不改变任何模型，只改变输出的**形状**，却能把复盘从"事后看涨跌"升级成"事后核对承诺"。

**怎么做：**

1. 在 `src/schema.mjs` 里把 `invalidation` 收紧：`level`（数值）、`series`（所指序列的 symbol）、`comparator`（above/below）、`by`（复检时点）**四个字段全部必填**，纯文字挪到 `note`。
2. 每个频道改出自己的数值化版本：
   - `narrative-shift` → tone 分数阈值 + 需要的文档数 + 统计窗口
   - `macro-transmission` → 明确 pair 的两条腿与基准序列，价差以 bp 计
   - `risk-flag` → 触发比率的具体数值门槛 + 需要连续几个报告期
3. `validate.mjs` 加检查：`invalidation-machine-testable`——任何进入已发布集合的卡，失效条件必须可被 `runReview` 求值。
4. 验收：`review` 报表里 `untestable = 0`。

## 3. 🟠 P1 · 禁止对无法判分的名义出方向卡

**证据。** 64 个已关窗口里 **13 条不可测**——卡片引用了价格库里没有的序列。

**为什么这是缺陷而不是数据缺口：** 一张事后无法判分的方向性卡，等于一张**在实践中不可证伪**的卡。而"每张卡都可证伪"是这个项目的三条主张之一。发一张自己永远没法核对的卡，比不发更糟。

**怎么做（两个都要）：**

1. **发布前守卫**：方向非 `neutral`/`avoid` 且 `instrument` 为 `native-equity` 的卡，若其标的在价格库里既没有自身序列、也没有声明的 `priceProxy`，则**不发布**，理由写进 trace。
2. **补数据**：把 `data/prices/` 从 25 个标的扩到覆盖语料里全部名义（`scripts/fetch-prices.mjs` 已经能拉，只是范围没铺满）。
3. 验收：`validate.mjs` 新增 `no-unscorable-directional-card`，且 `review` 报表里 `unmeasurable = 0`。

## 4. 🟠 P1 · 扩大独立观测

**证据。** 45 条已裁决主张只来自 **6 个不同的信息日期**；命中率的 Wilson 95% 区间是 **16.8–46.2%**（精确 CP 15.1–47.5%），比任何它可能测出的效应都宽。

**在这之前，任何校准数字都只是对这一块看板的描述，不是结论。** 报告里已经这么写了，路线图不改这个判断。

**怎么做：**

| 动作 | 目标 |
|---|---|
| 扩语料：更多**真实**财报/宏观文本，覆盖更长的历史区间 | 信息日期从 6 个 → **≥ 20 个** |
| 扩回放计划：`scripts/build-seed.mjs` 的 `REPLAY_DATES` 从 11 个日期铺到跨季度 | 独立窗口成倍增加 |
| 跨 regime：至少覆盖一段上涨、一段下跌、一段震荡 | 让 short 的 8.3% 能被判断是**方向性偏差**还是**这一段行情的 beta** |
| 目标样本 | **≥ 150 条决出胜负的主张** |

到那个量级，才谈得上"命中率""rho"这些词能当结论用。**在此之前不对外引用任何单个校准数字。**

## 5. 🟡 P2 · 接入真实 rToken 盘口

**证据。** `tradability` 因子（权重 0.18）里，rToken 的流动性系数是 **0.45——一个保守估算值**，不是从真实盘口测出来的。构建环境访问不到 Bitget 域名，所以这条**从未被真实数据校验过**。

**这是本项目最想接的一个数据源。**

**需要什么：** rToken 的**盘口深度**与**成交明细**（MCP 目前提供的是行情/基本面/财报日历/分析师预期这一层只读事实）。

**接到之后能做什么：**

- 用实测 spread / depth 替换 0.45，`tradability` 从猜测变成测量
- `closed-window` 频道可以给出**真实的**周末溢价/折价分布，而不是结构性论证
- `tradeSketch` 的入场价位可以按实际盘口做可行性校验，而不是按现金盘收盘价近似

**建议（已写进提交材料）：** MCP 若能补上盘口深度与成交明细这两个只读工具，这一整块就能落地。

---

## 6. 🟡 P2 · 抽取质量的系统性对比

**证据。** 标注抽取评测集只有 **10 例**（含 1 例阴性对照），账本评测 9 例（含故意掺入的编造数字）。双抽取器与对账逻辑**已实现且有测试**，但我们**没有**在标注集上系统对比过规则路径与 LLM 路径的准确率。

也就是说：**LLM 路径目前没有被证明带来任何增益。** 它存在、它能跑、它受同一个证据账本约束——但"它更好"这句话我们说不出口。

**怎么做：**

1. 标注集 10 → **100+ 例**，覆盖 7 个频道，每类都含阴性对照与幻觉注入
2. 固定 `--as-of`，同一批文档分别跑规则路径与 LLM 路径，输出**频道 × 字段**的准确率/召回率对照表
3. 重点看**账本拦截率**：LLM 路径产出多少被隔离的证据项？如果显著更高，说明"LLM 不享有豁免权"这条设计正在付成本，那就值
4. 验收：`docs/reports/extraction-comparison.md` 自动生成，两条路径的数字并排

---

## 7. 🟢 P3 · 成本与组合层

**证据。** 现有全部数字**不含佣金、价差、借券费、滑点**，也**没有组合层面的聚合**。

**这直接决定了项目的表述边界：** 在补上这一层之前，Prism **永远不能**发布任何 Sharpe / Sortino / 最大回撤数字。这不是谦虚，是算术——一次"命中"是一个方向，不是一笔利润。

**怎么做：** 仓位模型（按 `conviction` 与流动性系数）→ 逐笔成本模型 → 组合级净值曲线 → 才谈风险调整收益。**顺序不能颠倒**，跳过前两步直接画净值曲线就是自欺。

---

## 8. 🟢 P3 · live 端点端到端录制

**证据。** 构建环境无法访问 Bitget 域名，demo 与测试**全部**跑在 `offline` fixture 上。`auto` 模式的降级路径有测试覆盖，**live 路径没有在真实网络下验证过**。

**怎么做：** 在能出网的环境跑一次 `PRISM_DATA_MODE=live` 的完整 sweep，用 `scripts/record-fixtures.mjs` 把真实响应录成新 fixture，并在 `docs/VALIDATION.md` 里把「未在本环境验证」改成实测结果。

---

## 9. ⚪ P4 · 多用户与生产级持久化

**现状：** 看板状态是单机 JSON 文件（`data/state/board.json`），面向 demo 与研究，**不是生产存储**。

**要做的：** SQLite 或 Postgres 落库 → 用户/会话隔离 → 鉴权与限流 → 看板事件流的可查询历史。

**为什么排最后：** 这一项不改变任何已发布的数字，也不影响任何主张的可信度。它是"能不能给多人用"的问题，不是"判断对不对"的问题。在 P0 的符号反转修掉之前做产品化，等于把更多人接到一个**排序方向是反的**打分规则上。

## 10. 明确不做的事（non-goals）

| 不做 | 为什么 |
|---|---|
| **自动执行下单** | 那会把项目推到赛道二（Agentic Trading）。我们主动选了赛道三：**在当前阶段，让 LLM 全自主下单的核心障碍不是模型能力，而是问责链条。** P0 没修完之前，这条链还不配接下单 |
| **自动调打分权重** | 见 `REVIEW-LOOP.md` §4。样本非独立，自动调参 = 拟合噪声，且**不可追溯**。改规则永远是一次人类做的、写进 commit 的决定 |
| **把命中率当营销数字** | 29.4% 的 Wilson 95% 区间是 16.8–46.2%。引用它而不带区间和样本量，就是本项目反对的那种做法 |
| **给虚构发行主体配"真实感"更强的数据** | demo 语料里的 `CRVS`/`HLXN`/`ASTR`/`BLWF`/`NWCL` **是虚构的**，这是刻意的：只有虚构，"正确答案"才已知、才可判分。把它们做得更像真公司只会削弱这一点 |

---

## 11. 如果只有时间做一件事

**做 §2（失效条件数值化）。**

它不碰模型、不碰权重、不需要新数据源，只改变输出的**形状**；但它把复盘从"事后看涨跌"变成"事后核对 desk 自己写下的承诺"——也就是把这个项目从"一个会生成信号卡的工具"变成"一个**会为自己说过的话负责**的工具"。

而且它会立刻暴露 §1：一旦 24 条无法验证的失效条件变成可验证的，轴 ① 会开始真正裁决，那时 rho 是正是负才有意义。
